# Using LiteRTClient for On-Device LLM Inference in Koog

The `LiteRTClient` allows you to run Large Language Models (LLMs) locally on Android devices using Google's LiteRT runtime, via the MediaPipe LLM Inference API. This enables on-device text generation capabilities for your Koog agents.

## Overview

`LiteRTClient` implements the `ai.koog.prompt.executor.clients.LLMClient` interface, allowing it to be used with Koog's standard prompt execution framework (e.g., `SingleLLMPromptExecutor` or `MultiLLMPromptExecutor`).

**Current Status:**
*   Supports synchronous text generation (`execute` method).
*   Android platform only.

## Limitations (As of Current Version)

*   **Streaming Not Implemented**: The `executeStreaming` method is a placeholder and not yet functional.
*   **Multimodal Input Not Implemented**: While the client can be configured for vision capabilities (see `enableVision` in constructor), the actual processing of image inputs in prompts is not yet implemented.
*   **Tool Support**: LiteRT models, via the current MediaPipe API, do not support tool calling/function calling. This feature is unavailable.
*   **Token Counts**: `ResponseMetaInfo` generated by `LiteRTClient` will have `null` values for `totalTokensCount`, `inputTokensCount`, and `outputTokensCount` as this information is not directly available from the underlying LiteRT API.
*   **Emulator Support**: The underlying LiteRT runtime may not be reliably supported on all Android emulators. Testing on physical devices is recommended.

## Setup

### Dependencies

The `prompt-executor-litert-client` module includes the necessary MediaPipe dependency:
`com.google.mediapipe:tasks-genai:0.10.24` (or the version specified in its `build.gradle.kts`).

Your Android application utilizing this client will need appropriate permissions if downloading models at runtime (e.g., `android.permission.INTERNET`).

### Model File

`LiteRTClient` requires a LiteRT-compatible model file (ending in `.task`).
*   You are responsible for making this model file available on the Android device.
*   **Deployment**: For production, it's recommended to download the model from a server at runtime and store it in your app's private storage. The model path provided to `LiteRTClient` must be an absolute path to this file.
*   **Development/Testing**: You can use `adb push` to place the model on your device/emulator. For example:
    ```bash
    adb push your_gemma_model.task /data/local/tmp/my_model.task
    ```

## Instantiating LiteRTClient

`LiteRTClient` is an Android-specific component and must be instantiated in your Android application code.

```kotlin
import ai.koog.prompt.executor.litert.LiteRTClient
import android.content.Context

// Assuming 'appContext: Context' is available
val modelFilePath = "/data/local/tmp/my_model.task" // Or path to your downloaded model

val liteRTClient = LiteRTClient(
    context = appContext,
    modelPath = modelFilePath,
    // Optional parameters:
    maxTokens = 768,      // Default: 512
    topK = 40,            // Default: 40
    temperature = 0.7f,   // Default: 0.8f
    randomSeed = 123,     // Default: 0
    enableVision = false, // Default: false. Set to true if using a vision-capable model AND once multimodal input is implemented.
    maxNumImages = 1      // Default: 1. Relevant if enableVision is true.
)

// This client can now be used with a PromptExecutor, e.g.:
// val promptExecutor = SingleLLMPromptExecutor(liteRTClient)
```

**Constructor Parameters:**

*   `context: Context`: An Android `Context` (e.g., `ApplicationContext`).
*   `modelPath: String`: Absolute path to the `.task` model file on the device.
*   `clock: Clock` (Optional, Default: `Clock.System`): For timestamping responses.
*   `maxTokens: Int` (Optional, Default: 512): Maximum number of tokens (input + output) the model handles.
*   `topK: Int` (Optional, Default: 40): Limits predictions to the top K most probable tokens.
*   `temperature: Float` (Optional, Default: 0.8f): Randomness in generation. Higher is more creative.
*   `randomSeed: Int` (Optional, Default: 0): Random seed for text generation.
*   `enableVision: Boolean` (Optional, Default: `false`): Configures the client for vision models. **Note:** Actual image input processing is not yet implemented.
*   `maxNumImages: Int` (Optional, Default: 1): Maximum number of images, relevant if `enableVision` is true.

## Basic Usage (Synchronous Text Generation)

Use the `execute` method for text-only prompts:

```kotlin
import ai.koog.prompt.dsl.prompt
import ai.koog.prompt.llm.LiteRTModels // Assuming you have your LiteRT model defined here
import kotlinx.coroutines.runBlocking // For example

// Assuming 'liteRTClient' is initialized as above
// Assuming 'promptExecutor' is SingleLLMPromptExecutor(liteRTClient) or similar

val myPrompt = prompt {
    system("You are a helpful AI assistant.")
    user("What is the capital of Germany?")
}

// Define your LiteRT model (ensure its ID matches what you expect)
val gemmaModel = LiteRTModels.Gemma3n.E2B // Example

runBlocking { // Example of calling from a coroutine
    try {
        val responses = liteRTClient.execute(myPrompt, gemmaModel, emptyList())
        // Or using a PromptExecutor:
        // val responses = promptExecutor.execute(myPrompt, gemmaModel)

        if (responses.isNotEmpty()) {
            val assistantResponse = responses.first() as ai.koog.prompt.message.Message.Assistant
            println("LiteRT Model Response: ${assistantResponse.content}")
            // assistantResponse.metaInfo will contain timing info but not token counts
        }
    } catch (e: Exception) {
        println("Error executing LiteRT prompt: ${e.message}")
        // Handle exceptions (e.g., model loading issues, runtime inference errors)
    }
}
```

### Prompt Input Formatting

For the `execute` method, `LiteRTClient` currently constructs the input string for the LiteRT model by:
1.  Concatenating the content of all `Message.System` messages (if any), separated by newlines.
2.  Appending the content of all `Message.User` messages (if any), separated by newlines.
Other message types (Assistant, ToolCall, ToolResponse) are currently ignored for input construction in basic text mode.

## Error Handling

*   **Initialization**: If `LiteRTClient` fails to initialize (e.g., model file not found at `modelPath`, LiteRT runtime issue), it will throw an `IllegalStateException`.
*   **Execution**: If an error occurs during prompt execution (inference), it will throw a `RuntimeException`.
Ensure your application code includes appropriate try-catch blocks.
