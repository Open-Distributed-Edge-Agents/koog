# Using LiteRTClient for On-Device LLM Inference in Koog

The `LiteRTClient` allows you to run Large Language Models (LLMs) locally on Android devices using Google's LiteRT runtime, via the MediaPipe LLM Inference API. This enables on-device text generation and multimodal (text and image) capabilities for your Koog agents.

## Overview

`LiteRTClient` implements the `ai.koog.prompt.executor.clients.LLMClient` interface, allowing it to be used with Koog's standard prompt execution framework (e.g., `SingleLLMPromptExecutor` or `MultiLLMPromptExecutor`).

**Current Status:**
*   Supports synchronous text and multimodal (text+image) generation (`execute` method).
*   Supports streaming text and multimodal (text+image) generation (`executeStreaming` method).
*   Android platform only.

## Key Features
*   **Text Generation**: Standard text-based prompting.
*   **Streaming Text Generation**: Receive text responses as a stream of chunks.
*   **Multimodal Input (Text + Image)**: Provide both text and a single image as input to compatible vision models (e.g., Gemma 3n).
    *   Supports images provided as `AttachmentContent.URL`, `AttachmentContent.Binary.Bytes`, or `AttachmentContent.Binary.Base64`.
    *   The client will process the *first* `Attachment.Image` found in the `Message.User` attachments.

## Limitations (As of Current Version)

*   **Single Image Only**: For multimodal inputs, only the first image found in user messages is processed. LiteRT (with Gemma 3n) currently supports one image per inference session.
*   **Tool Support**: LiteRT models, via the current MediaPipe API, do not support tool calling/function calling. This feature is unavailable.
*   **Token Counts**: `ResponseMetaInfo` generated by `LiteRTClient` will have `null` values for `totalTokensCount`, `inputTokensCount`, and `outputTokensCount` as this information is not directly available from the underlying LiteRT API.
*   **Emulator Support**: The underlying LiteRT runtime may not be reliably supported on all Android emulators. Testing on physical devices is recommended.

## Setup

### Dependencies

The `prompt-executor-litert-client` module includes the necessary MediaPipe dependency:
`com.google.mediapipe:tasks-genai:0.10.24` (or the version specified in its `build.gradle.kts`).

Your Android application utilizing this client will need appropriate permissions if downloading models at runtime (e.g., `android.permission.INTERNET`).

### Model File

`LiteRTClient` requires a LiteRT-compatible model file (ending in `.task`).
*   The `modelPath` parameter in the `LiteRTClient` constructor must be an absolute path to this file on the Android device.
*   **Application Responsibility**: Your application is responsible for ensuring this model file is present at the specified path. This might involve:
    *   Bundling a model with your app (if very small, generally not recommended for LLMs).
    *   Providing functionality within your app to download the model file from a server and store it in app-specific storage. The Koog Demo Android App includes an example of such a downloader.
    *   Instructing users to manually place the model file and provide its path (less user-friendly).
*   **Storage**: It's recommended to store downloaded models in your app's private storage (e.g., using `context.getExternalFilesDir(null)` or `context.filesDir`) to avoid needing broad storage permissions.
*   **Development/Testing**: You can use `adb push` to place the model on your device/emulator for development. For example:
    ```bash
    adb push your_gemma_model.task /data/local/tmp/my_model.task
    ```

## Instantiating LiteRTClient

`LiteRTClient` is an Android-specific component and must be instantiated in your Android application code.

```kotlin
import ai.koog.prompt.executor.litert.LiteRTClient
import android.content.Context

// Assuming 'appContext: Context' is available
val modelFilePath = "/data/local/tmp/my_model.task" // Or path to your downloaded model

val liteRTClient = LiteRTClient(
    context = appContext,
    modelPath = modelFilePath,
    // Optional parameters:
    maxTokens = 768,      // Default: 512
    topK = 40,            // Default: 40
    temperature = 0.7f,   // Default: 0.8f
    randomSeed = 123,     // Default: 0
    enableVision = false, // Default: false. Set to true if using a vision-capable model AND once multimodal input is implemented.
    maxNumImages = 1      // Default: 1. Relevant if enableVision is true.
)

// This client can now be used with a PromptExecutor, e.g.:
// val promptExecutor = SingleLLMPromptExecutor(liteRTClient)
```

**Constructor Parameters:**

*   `context: Context`: An Android `Context` (e.g., `ApplicationContext`).
*   `modelPath: String`: Absolute path to the `.task` model file on the device.
*   `clock: Clock` (Optional, Default: `Clock.System`): For timestamping responses.
*   `maxTokens: Int` (Optional, Default: 512): Maximum number of tokens (input + output) the model handles.
*   `topK: Int` (Optional, Default: 40): Limits predictions to the top K most probable tokens.
*   `temperature: Float` (Optional, Default: 0.8f): Randomness in generation. Higher is more creative.
*   `randomSeed: Int` (Optional, Default: 0): Random seed for text generation.
    *   `enableVision: Boolean` (Optional, Default: `false`): **Required to be `true` for multimodal (image) input.** Configures the client to prepare for vision models.
    *   `maxNumImages: Int` (Optional, Default: 1): Configures the underlying LiteRT task for the maximum number of images. Currently, only 1 is effectively supported by the client and Gemma 3n models.

## Usage Examples

### 1. Synchronous Text Generation

Use the `execute` method for text-only prompts:

```kotlin
import ai.koog.prompt.dsl.prompt
import ai.koog.prompt.llm.LiteRTModels // Assuming you have your LiteRT model defined here
import kotlinx.coroutines.runBlocking // For example

// Assuming 'liteRTClient' is initialized as above
// Assuming 'promptExecutor' is SingleLLMPromptExecutor(liteRTClient) or similar

val myPrompt = prompt {
    system("You are a helpful AI assistant.")
    user("What is the capital of Germany?")
}

// Define your LiteRT model (ensure its ID matches what you expect)
val gemmaModel = LiteRTModels.Gemma3n.E2B // Example

runBlocking { // Example of calling from a coroutine
    try {
        val responses = liteRTClient.execute(myPrompt, gemmaModel, emptyList())
        // Or using a PromptExecutor:
        // val responses = promptExecutor.execute(myPrompt, gemmaModel)

        if (responses.isNotEmpty()) {
            val assistantResponse = responses.first() as ai.koog.prompt.message.Message.Assistant
            println("LiteRT Model Response: ${assistantResponse.content}")
            // assistantResponse.metaInfo will contain timing info but not token counts
        }
    } catch (e: Exception) {
        println("Error executing LiteRT prompt: ${e.message}")
        // Handle exceptions (e.g., model loading issues, runtime inference errors)
    }
}
```

### 2. Streaming Text Generation

Use the `executeStreaming` method to receive text output as a Kotlin `Flow` of strings:

```kotlin
import ai.koog.prompt.dsl.prompt
import ai.koog.prompt.llm.LiteRTModels
import kotlinx.coroutines.flow.collect
import kotlinx.coroutines.launch
import kotlinx.coroutines.runBlocking // For example

// Assuming 'liteRTClient' is initialized
val myStreamingPrompt = prompt {
    user("Write a short story about a robot learning to paint.")
}
val gemmaModel = LiteRTModels.Gemma3n.E2B // Example

runBlocking { // Example of calling from a coroutine
    launch { // Launch a new coroutine for collecting the flow
        try {
            println("LiteRT Streaming Response:")
            liteRTClient.executeStreaming(myStreamingPrompt, gemmaModel)
                .collect { chunk ->
                    print(chunk) // Print each chunk as it arrives
                }
            println("\n--- End of Stream ---")
        } catch (e: Exception) {
            println("\nError during LiteRT streaming: ${e.message}")
            // Handle exceptions
        }
    }
}
```

### 3. Multimodal Input (Text + Image)

To provide an image along with text, include an `Attachment.Image` in your `Message.User`. Ensure `LiteRTClient` is initialized with `enableVision = true` and the `LLModel` used has `LLMCapability.Vision`.

```kotlin
import ai.koog.prompt.dsl.prompt
import ai.koog.prompt.llm.LiteRTModels
import ai.koog.prompt.message.Attachment
import ai.koog.prompt.message.AttachmentContent
import android.graphics.Bitmap // Assuming you have a Bitmap instance
// ... other necessary imports ...

// Assuming 'liteRTClientWithVision' is initialized with enableVision = true
// val liteRTClientWithVision = LiteRTClient(appContext, modelFilePath, enableVision = true)

// Example: Creating an Attachment.Image from a Bitmap
// (In a real app, you might load this from a file, camera, or gallery)
// val myBitmap: Bitmap = ... your bitmap ...
// val outputStream = java.io.ByteArrayOutputStream()
// myBitmap.compress(Bitmap.CompressFormat.JPEG, 85, outputStream)
// val imageBytes = outputStream.toByteArray()
// val imageAttachment = Attachment.Image(
//    content = AttachmentContent.Binary.Bytes(imageBytes),
//    format = "jpeg"
// )

// For this example, let's assume imageAttachment is already prepared:
// val imageAttachment: Attachment.Image = ...

val multimodalPrompt = prompt {
    user("Describe what you see in this image.", imageAttachment) // Add imageAttachment here
}

// Ensure your model definition includes LLMCapability.Vision
val visionModel = LiteRTModels.Gemma3n.E2B.copy(
    capabilities = LiteRTModels.Gemma3n.E2B.capabilities + LLMCapability.Vision
)


// Synchronous Execution:
runBlocking {
    try {
        val responses = liteRTClientWithVision.execute(multimodalPrompt, visionModel, emptyList())
        if (responses.isNotEmpty()) {
            println("Multimodal Response: ${responses.first().content}")
        }
    } catch (e: Exception) {
        println("Error in multimodal execution: ${e.message}")
    }
}

// Streaming Execution:
runBlocking {
    launch {
        try {
            println("Multimodal Streaming Response:")
            liteRTClientWithVision.executeStreaming(multimodalPrompt, visionModel)
                .collect { chunk ->
                    print(chunk)
                }
            println("\n--- End of Multimodal Stream ---")
        } catch (e: Exception) {
            println("\nError during multimodal streaming: ${e.message}")
        }
    }
}
```
**Note on Image Attachments:**
*   The client processes the first `Attachment.Image` found in `Message.User` attachments.
*   Supported `AttachmentContent` types for images are:
    *   `AttachmentContent.Binary.Bytes(byteArray)`
    *   `AttachmentContent.Binary.Base64(base64String)`
    *   `AttachmentContent.URL(urlString)` (image will be downloaded)
*   The client includes basic image compression and resizing if the image is very large, to improve stability and performance with the LiteRT runtime.

### Prompt Input Formatting

For the `execute` method, `LiteRTClient` currently constructs the input string for the LiteRT model by:
1.  Concatenating the content of all `Message.System` messages (if any), separated by newlines.
2.  Appending the content of all `Message.User` messages (if any), separated by newlines.
Other message types (Assistant, ToolCall, ToolResponse) are currently ignored for input construction in basic text mode.

## Error Handling

*   **Initialization**: If `LiteRTClient` fails to initialize (e.g., model file not found at `modelPath`, LiteRT runtime issue), it will throw an `IllegalStateException`.
*   **Execution**: If an error occurs during prompt execution (inference), it will throw a `RuntimeException`.
Ensure your application code includes appropriate try-catch blocks.
